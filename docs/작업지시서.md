# 작업지시서: 50분을 지켜라

> 문구·데이터의 원본은 `50분을_지켜라_게임기획안.md` 4장. 이 문서는 동작과 규칙을 정의한다.
> 충돌 시 이 문서의 규칙이 우선, 문구는 기획안이 우선.

---

## 0. 공통 규칙

- 화면은 `#app` 안에 한 번에 하나만 렌더링한다. `showScreen(name)`으로 전환.
- 화면 5개: `start` → `prep` → `live` → `post` → `result`. 뒤로 가기 없음. `result`의 [다시 하기]는 상태를 초기화하고 `start`로.
- 기준 화면: 스마트폰 세로 360×640. 태블릿·노트북에서는 가운데 정렬, 최대 너비 480px.
- 터치 영역 최소 44×44px. 모든 버튼은 `<button>` 요소.
- 색만으로 상태를 구분하지 않는다. 아이콘(이모지)+텍스트를 같이 쓴다.

### 게임 상태 (`state.js`)
```js
state = {
  prep: { selected: [],  score: 0, max: 40 },              // 고른 카드 id
  live: { clock: 0, score: 0, max: 0, handled: [], missed: [], foundHidden: [] },
  records: [],                                              // 수업 후로 넘길 기록 카드 id
  post: { score: 0, max: 0, answered: [] },
  flags: { battery_low: false, wifi_three: false, url_error: false, noTeacherDeal: false, noBackup: false, extraHidden: false }
}
```
- 점수 변경 함수: `addScore(phase, n)`, `addMax(phase, n)`. 단계별 %는 `Math.round(score / max * 100)`, 음수면 0, max가 0이면 100.

## 1. 시작 화면 (`start`)

**시나리오**: 연수생이 QR로 접속하면 바로 이 화면이 뜬다.

**요소**
- 제목 「50분을 지켜라」, 부제 "24명 교실의 디지털 튜터가 되어 50분을 지켜 주세요"
- 시나리오 카드: 6학년 3반 · 학생 24명 · 갤럭시탭 1인 1기기 · 수업: 우리 지역 소개 자료 만들기(패들렛 + AI 피드백)
- 진행 안내 3줄: 수업 전 준비 → 수업 중 대처(①~④ 선택) → 수업 후 조치
- [시작] 버튼 → `prep`

**완성 기준**
- [ ] 스마트폰 세로 화면에서 스크롤 없이 [시작] 버튼이 보인다

## 2. 수업 전 (`prep`)

**시나리오**: "수업 시작 10분 전" 안내를 보고, 8장 중 4장을 골라 [수업 시작]을 누른다.

**화면 동작**
1. 상단: "준비할 시간이 부족해요. 4장만 고르세요." + 선택 수 표시 `2 / 4`
2. 카드 8장을 2열 그리드로 표시. 순서는 매번 섞는다.
3. 카드를 누르면 선택/해제 토글. 4장이 선택된 상태에서 다른 카드를 누르면 무시하고 "4장까지만 고를 수 있어요" 토스트.
4. [수업 시작]은 정확히 4장 선택 시에만 활성화.
5. 누르면 결과 패널: 고른 카드마다 점수(+10/−10)와 피드백 한 줄. [교실로 들어가기] → `live`

**데이터 흐름**
- 좋은 카드 +10, 위험 카드(`prep_pw_list`, `prep_prelogin`) −10 → `state.prep.score`
- 고르지 않은 카드에 따라 flags 설정:
  - `prep_charge` 미선택 → `flags.battery_low = true`
  - `prep_wifi` 미선택 → `flags.wifi_three = true`
  - `prep_login` 미선택 → `flags.url_error = true`
  - `prep_teacher` 미선택 → `flags.noTeacherDeal = true` (수업 중 "선생님께 알리기"가 최선인 선택지 점수 +10 → +5)
  - `prep_backup` 미선택 → `flags.noBackup = true` (`url_error`의 "대체 활동지" 선택지를 목록에서 제외하고 3지선다로)
  - `prep_seat` 미선택 → `flags.extraHidden = true` (`peek_friend` 외에 숨은 사건 1개 추가: `shy_ask`)

**완성 기준**
- [ ] 4장 미만/초과로는 진행할 수 없다
- [ ] 위험 카드를 고르면 결과 패널에 감점과 이유가 보인다
- [ ] 고르지 않은 카드에 맞는 flags가 설정된다 (콘솔로 확인)

## 3. 수업 중 (`live`)

**시나리오**: 시계가 흐르고, 학생 아이콘에 문제가 생기면 눌러서 4지선다로 대처한다.

**화면 요소**
- 상단 바: 시계 `⏱ 13:24 / 50:00`, 수업 단계 칩 4개(도입 0~10분 / 활동1 10~20분 / 활동2 20~35분 / 정리 35~50분, 현재 단계 강조), 총점 `⭐ 120`
- 교사 영역: "선생님 · 전자칠판" + 현재 활동 문구
- 좌석 6열×4행, 1~24번. 각 좌석에 상태 아이콘 + 번호
- 하단: [👀 둘러보기] (쿨다운 중이면 남은 시간 표시, 비활성), [📝 기록장 N] (누르면 지금까지 기록 목록 보기, 시계 정지)

**시간 진행**
- `setInterval` 1초마다 게임 시계 +12초 (게임 1분 = 실제 5초, 50분 ≈ 4분 10초)
- 모달(상황 카드·기록장)이 열려 있으면 정지
- 50:00 도달 → "수업 종료" 오버레이 1.5초 → `post`

**사건 발생**
- `events.js`의 각 사건은 `time`(게임 분), `seat`, `visible`, `condition`(flags 키 또는 없음)을 가진다
- 시계가 `time`에 도달하고 `condition`이 참이면 해당 좌석 상태 변경: visible → ⚠️ 또는 🙋, hidden → 겉으로는 🙂 유지
- 발생과 동시에 `state.live.max += 10`
- 발생 후 게임 6분 동안 처리되지 않으면 💤, `state.live.missed`에 추가, −5점. 💤 좌석은 더 이상 누를 수 없다

**둘러보기**
- 누르면 3초 동안 숨은 사건이 발생한 좌석이 😶로 보인다. 쿨다운 게임 5분
- 😶가 보이는 동안 누르면 상황 카드가 열리고 `foundHidden`에 추가, 보너스 +5 (`max`에도 +5)
- 3초 뒤 다시 🙂로 보이지만 사건은 남아 있다 (6분 지나면 💤)

**상황 카드 모달 (`choice.js`, 수업 중·수업 후 공용)**
- 상단: 좌석 번호 + 분류 칩(예: `접근 · 계정`) + 상황 문장
- 선택지 ①②③④ 버튼. 순서는 매번 섞되 번호 라벨은 화면 순서대로 ①~④
- 15초 카운트다운 바. 0이 되면 "망설이는 사이 시간이 지났어요" + 0점 처리
- 선택 즉시: 선택지 버튼 비활성, 고른 선택지에 점수 배지(+10/+5/0/−5), 피드백 1~2문장, [계속]
- 선택지에 `record` 값이 있으면 `state.records`에 추가하고 "📝 기록장에 남겼어요" 표시
- [계속] → 모달 닫기, 좌석 🙂로 복귀, 시계 재개

**완성 기준**
- [ ] 수업 전에 고른 카드에 따라 추가 사건이 나오고/안 나온다
- [ ] 모달이 열려 있는 동안 시계가 멈춘다
- [ ] 방치한 사건은 6분 뒤 💤가 되고 감점된다
- [ ] 숨은 학생은 둘러보기 없이는 보이지 않는다
- [ ] 1판이 실제 4분 30초 안에 끝난다 (모달 시간 제외)

## 4. 수업 후 (`post`)

**시나리오**: 기록장에 남긴 문제를 하나씩 누구에게 어떻게 넘길지 고른다.

**화면 동작**
1. 상단: "수업이 끝났어요. 기록장을 보며 마무리해 주세요." + 진행 `1 / 4`
2. `state.records` 순서대로 기록 카드를 하나씩 상황 카드 모달(`choice.js`)로 보여 준다. 카드당 `max += 10`
3. 기록 카드가 끝나면 마지막 문항 "다음 수업 전에 꼭 점검할 것 1개는?" (`max += 10`). 정답은 기록장 내용에 맞춰 `records.js`의 `finalQuestion` 규칙으로 결정
4. 수업 중에 기록하지 않아서 빠진 카드가 있으면, 끝에 회색 카드로 목록 표시: "기록하지 않은 문제: 12번 태블릿 → 다음 수업에 다시 생깁니다" (점수 없음)
5. [결과 보기] → `result`

**엣지 케이스**
- `state.records`가 비어 있으면 1번 단계를 건너뛰고 "기록장이 비어 있어요. 기록하지 않은 문제는 다음 수업에 다시 생깁니다." 안내 후 마지막 문항만 진행

**완성 기준**
- [ ] 수업 중 기록한 카드만 나온다
- [ ] 기록하지 않은 문제가 회색 목록으로 보인다
- [ ] 기록장이 비어 있어도 화면이 깨지지 않는다

## 5. 결과 (`result`)

**화면 요소**
1. 총점 ⭐ (세 단계 점수 합)
2. 단계별 % 막대 3개: 수업 전 / 수업 중 / 수업 후
3. 칭호 카드 (`titles.js`)
   - 세 단계 모두 80% 이상 → 🛡 수업 지킴이
   - 아니면 %가 가장 높은 단계: 📋 준비의 달인 / 👀 대처의 달인 / 🔗 마무리의 달인
   - 동점 우선순위: 수업 중 > 수업 후 > 수업 전
4. 다음 판 과제: %가 가장 낮은 단계의 문구 (동점 우선순위: 수업 후 > 수업 중 > 수업 전). 수업 지킴이여도 표시
5. 놓친 학생 리포트: `💤 2명 — 참여 격차 1명, 활용 격차 1명` (사건의 `gap` 값으로 집계). 0명이면 "놓친 학생 없이 50분을 지켰어요"
6. 결과 코드: `82-75-90-👀` (수업 전%-수업 중%-수업 후%-칭호 이모지), 큰 글씨
7. [다시 하기] → 상태 초기화 → `start`

**완성 기준**
- [ ] 칭호·다음 판 과제가 규칙대로 나온다 (단계별 % 조합 3가지 이상 수동 테스트)
- [ ] 스마트폰 한 화면에 결과 코드까지 보인다 (캡처 공유용)

## 6. 데이터 파일 형식

```js
// js/data/prepCards.js
export const prepCards = [
  { id: 'prep_charge', text: '충전함 배터리 확인', good: true, score: 10, feedback: '...' },
  // ... 8장
];

// js/data/events.js
export const events = [
  { id: 'freeze_12', time: 18, seat: 12, visible: true, condition: null,
    category: '기기', gap: null, text: '...',
    choices: [ { text: '...', score: 10, record: 'rec_device12', feedback: '...', needs: null }, ... ] },
  // condition 예: 'battery_low' → flags.battery_low가 true일 때만 발생
  // needs 예: 'backup' → flags.noBackup이 true면 이 선택지 제외
  // teacherCall: true → flags.noTeacherDeal이 true면 score 10 → 5
];

// js/data/records.js
export const records = [ { id: 'rec_device12', title: '12번 태블릿', text: '...', choices: [...] }, ... ];
export const finalQuestion = { text: '다음 수업 전에 꼭 점검할 것 1개는?', choices: [...] };

// js/data/titles.js
export const titles = { guard: {...}, prep: {...}, live: {...}, post: {...} };
export const nextTasks = { prep: '...', live: '...', post: '...' };
```
- 사건 13개, 기록 카드 6장, 점검 카드 8장의 문구는 기획안 4-2·4-3·4-4 표에서 가져온다. 기획안에 선택지가 1개만 있는 경우 나머지 3개(차선·아쉬움·잘못)는 기획안 "선택지 점수 규칙"에 맞춰 작성하고, 작성한 문구 목록을 형에게 보여 확인받는다.
- `gap` 값: '접근' | '활용' | '이해' | '참여' | null (보안·기기 사건은 null)
